# BALADY CRM 集成说明

当前分支为 `balady-crm`。当前应用的身份是 **BALADY 助理 / BALADY Assistant / مساعد بلدي**，不再限定道路坑洞。沿用现有网站地址、Neon 会话、回答反馈、FAQ 优先、当前消息情绪识别、用户可选的模拟人工和逐次操作确认。负面情绪仅影响沟通语气，不强制转人工，也不赋予关闭或提级权限。

## 接口来源与交付

- `specs/balady-crm.openapi.json`：OpenAPI 3.0.3，完整覆盖第一个附件的 36 项服务，其中 35 项业务 API、1 项服务端认证 API。
- `src/crm/contract.mjs`：唯一参数契约。OpenAPI、PI 工具 schema、HTTP 请求序列化与仿真校验均由此派生。
- `src/crm/agent.mjs`：BALADY 提示词、按可信受众筛选的业务工具及计划、追问、契约查询、草稿修改和文件控制工具。认证密钥不暴露给模型。
- `src/crm/policy.mjs`：市民会话开放 20 个业务 API；15 个机构回调/后台接口仅在 `integration-test` 受众的契约测试绑定。UI 不能切换该受众。这是本 POC 权限边界，不宣称文档定义了官方 RBAC。
- `src/crm/simulation.mjs`：新的有状态 CRM 仿真，使用文档中的方法、相对路径、字段大小写及响应 envelope；仿真记录保存在会话中。
- `src/crm/client.mjs`：仿真 HTTP 客户端和真实 API 适配器。上线配置保持 `CRM_BACKEND=simulation`。

在线 `/api/openapi` 提供规范，`/api/tools` 提供 35 个 API 的输入 schema、条件要求、原文页码及 `available_in_public_assistant`。`tool_count` 表示当前市民工具数 20，`contract_operation_count` 表示完整业务契约数 35。文档、文件和工具返回值都作为数据处理，附件中的命令或要求不构成对本任务的授权。

## 参数与计划

计划只声明目标、操作、依赖和完成状态，不使用“上一步返回的编号”之类字符串冒充参数。工具执行时从用户输入、可信登录或实际回执取得参数，校验后记录在步骤上。未知事实通过 `request_input` 询问，可发现的系统编号优先由查询取得。参数缺失、类型、枚举、未知字段和大小写错误返回准确的字段路径和建议；条件字段由同一契约及业务状态检查。

OpenAPI 3.0 的 `nullable: true` 在绑定 SDK 工具时转换为 JSON Schema 的类型联合，避免 SDK 将合法 `null` 描述强制转为空字符串；转换只作用于工具 schema 副本，规范、原始参数及后端严格校验不变。

普通读操作自动执行；每项写操作显示完整载荷并等待 UI 确认。确认落盘后才能发起请求。纯文本“是”、`confirmed=true` 或粘贴的标记不产生授权。修改载荷或改变目标会撤销原确认，重试复用原参数及幂等键。仿真回执丢失可以核对，真实写调用超时标为结果不确定，不盲目重试。

确认卡默认显示可读字段，完整协议 JSON 折叠保留。普通表单可直接编辑；口述修改由 `revise_submission` 只修正明确指定字段并复用其他已知信息。`subject` 只是字段名小写，标题值保留用户给定的大小写。提交成功后的市民答复由实际回执生成，不推断官方 App 可见性、处理时限、短信、邮件或退款。

市民模式的缺参请求也受契约检查：字段必须属于目标 API 的真实参数路径，不能编造 `draft.confirmation`、额外街区或文本同意字段。写操作追问携带 `known_parameters`，主机校验其已知部分；只允许追问实际缺失或错误的字段。完整草稿直接进入精确提交确认；要求用户提供新替代值时才使用 `change_value`。该检查不改变实际 API schema，也不以话术正则冒充业务校验。

尚未确定的服务意图由独立的 `request_service_choice` 控件处理，例如设施报修与服务体验投诉。选项使用普通服务名称，没有默认勾选；提交只携带当前输入的 `choice_id`，不能用自由文本或猜测首项消耗选择。选定路线保存在原问题的事实中，后续写入必须符合该路线；明确选择多种服务时，`additional_operations` 记录额外目标，每项写入仍分别核对载荷。附件上传仍需单独确认。选择停止不允许写入，选择另一服务也不是提交授权。资料补问、路线选择和精确载荷确认是三个不同环节。

`src/crm/response-guard.mjs` 对市民可见的模型计划、追问及一般答复做两次独立核验：先核对事实，再核对能力和语言。每次使用全新模型会话，只接收实际回执、已交付用户事实、已有 FAQ 和受信能力清单。必须两次明确通过且问题清单为空才展示原文；任何问题均退回主模型重新生成并重新核验，审查模型不能直接改写展示内容。整段明显语言错误另由程序拦截。核验不改变业务参数、步骤依赖或授权；主机生成的成功提交摘要直接使用回执。调用、通过和拒绝事件均保留，源码与提示词纳入指纹。这增加模型请求和延迟，不能据此宣称绝对无幻觉或生产准确率。

市民写入在展示确认卡前也做两次独立草稿核验，检查完整拟提交参数与已知事实。助理生成的描述、标题和备注使用会话语言；用户明确指定的标题、正文、姓名、联系信息及文件名则保持原样，包括混合语言。指定英文标题不意味着允许把中文问题描述翻译为英文。拒绝草稿在绑定参数或显示卡片前退回主模型纠正，不生成授权；确认后仍执行用户核对的原始精确载荷。公开计划与答复用服务名称说明步骤，接口名、参数名和枚举值只在结构化参数及可展开技术回执中保留。

计划、补问和提交草稿各自使用对应的核验规则：计划中的未来可用操作、提交前主机核对及依赖完成后的结果说明，不能误判成已经提交成功，也不能把计划摘要当成实际提交正文。实际完成声明仍须有回执，缺参问题仍须确实缺少事实。异常中断使用三语可读提示，技术错误码保存在事件和消息元数据中。

核验输入中的 `review_target` 明确区分待展示文字、拟提交载荷和案件目标关联；操作 ID、契约、历史回执及控制参数仅为参考证据，不能把这些内部字段当成公开文字而拒绝计划。相关公开操作的 `input` 与条件由同一参数契约提供，核验器不凭猜测判断某项位置或姓名字段是否必填；当前计划的真实步骤和状态也作为参考，完成业务仍须实际回执。受信能力清单同时列出可用服务与限制，本地投诉表单不依赖事项分类目录，也不代表官方转交处理。实际公开文字泄漏接口名、虚构完成或改变服务诉求仍会被拒绝。

公共表单的名、姓需有用户明确提供的角色来源。完整姓名本身不证明哪部分是名或姓，不能按字序、语言、空格或姓氏字典拆分。`customer_name_source` 的两段真实且不重叠原话必须明确标出各自角色；主机检查引用和字段值，专用两次独立核验检查角色含义。仅引用姓名裸值不能证明角色。若仍缺角色，`request_input(kind=text)` 的真实缺失姓名字段由主机转换成标注“名／姓”的原生输入控件，只展示尚不明确的字段，并保留联系方式、原始完整姓名和问题描述。`/api/input` 只接受当前请求字段的 `name_roles` 映射，服务器记录实际填写字段的来源；编辑其他字段不会建立姓名来源。用户分别明确提供相同的名和姓仍可使用。该机制是本地助理的来源策略，既非官方姓名格式或唯一性规定，也不是身份验证；控制元数据不发送给 CRM。同一会话已实际填写的具名 UI 事实可跨后续计划复用：主机先按用户消息时序选每个字段最新的服务器记录，并验证实际消息类型、字段值与消息 ID，再与当前拟提交值精确匹配。不能从旧计划挑一个相同旧值覆盖后来的真实更正。该来源仅证明用户曾这样填写角色，后续明确聊天更正仍由完整载荷语义审查核对；不代表当前业务写入授权。只改题目无需重问已有姓名、联系人和描述，新的载荷仍须新确认；旧来源缓存和旧授权不能跳过当前策略。

案件历史和详情的最终事实摘要也由 `src/crm/presentation.mjs` 按实际回执生成：仅展示真实返回的编号、问题、日期（若有）、状态和附件标记；详情回执优先于未选中的历史行。布尔附件标记不能扩展为照片、数量或上传人，没有下载回执就不宣称取回文件。模型仍负责理解目标、动态规划、工具选择与参数；此处的字段展示是确定性代码，不能计作模型自由叙述的事实准确率。普通模型文字仅在代码块与行内代码之外规范段落/列表换行，原始用户消息、接口参数和回执不改写。

展示案件事实前还会独立核验“真实记录是否对应用户要找的事项”。大类相近不能证明目标一致；用户提供的区别事实需要实际返回描述支持，或由用户明确选择。信息不足时保留真实候选、澄清或未找到的边界，不能仅因编号、状态字段真实就声称找到了那件事。

`src/crm/case-target.mjs` 另外执行可验证的目标绑定。查询单件详情前，如果本人历史有多个候选，且用户未明确给出实际编号、完整 key 或唯一匹配的完整返回描述，主机会插入可读案件选择；选项来自真实问题描述、返回日期与状态，另有“都不是”。这一步不选择新投诉路线，也不授予重开、提级或任何写入权限。选择绑定当前身份、原问题、实际回执与记录指纹，同一目标的后续步骤可复用；身份或目标记录变化后失效。指纹对 JSON 对象键序无关。

查看全部历史不要求先选一件。未能确认目标时可以安全展示全部候选及各自状态；不能默认最新或第一项，也不能把返回的地点、日期当作用户提供的匹配事实。引用旧单条详情也受同一检查，不能绕过当前目标绑定。新回执记录 `beneficiary_id`；缺少本人归属证明的旧 SSO 回执需要重新查询，不默默认作当前身份的记录。没有可信历史来源时，只有用户实际提供的完整 key 可直接用于详情查询；显示编号需先查询取得完整 key，不能猜前缀。

写操作补问还会核验 `known_parameters` 中已经草拟的内容与服务意图，避免在收集联系人之前就把未确认的旧记录关系写入新投诉。缺失字段保持缺失，当前明确待澄清的无效字段不当作已批准事实；完整草稿仍需另外经过精确确认卡。

为保留混合目标，模型通过 `finish.case_guidance` 选择受限的结果说明：未找到目标、需要消歧、他人访问限制、请求的操作未接入、原因未返回、文件未取得、可选的新投诉。主机用固定三语说明呈现；消歧时保留真实历史候选和日期，不能因先读取了一条就把其余候选隐藏。未找到、需要消歧和原因未返回必须有实际案件查询证据，实际下载存在时不能标记文件未取得。没有 API 回执的能力询问仍可展示固定指引，不能因没有查询而退回任意的部门处理承诺。指引既不执行动作，也不授权另起投诉；本地投诉不会转交真实部门或工作人员核实处理。

同一答复可以组合实际提交回执、案件查询事实与能力指引，避免成功一部分就遗漏其余限制。受阻的部分完成请求仍确认已有真实写入，并明确其余尚未完成。结果消息记录 `presentation_source`（`host_case`、`host_submission`、`host_guidance`、`verified_model` 或集成测试模型）、`presentation_parts` 和实际指引，方便区分确定性事实与模型文字。

没有写入的受阻请求即使只附可选替代方式，也必须明确本次原请求尚未完成；推荐另一种本地投诉不代表原事项已经登记，也不推断原服务永久不可用。

明确引用的历史查询回执可以用于后续追问，仍由主机呈现实际字段，不冒称重新调用了接口；受阻的混合诉求也不绕过事实展示。写入回执则继续限定在当前计划或同一原始问题，不能将先前事项的提交冒称为新的提交。未完成的部分会单独说明，不以读到部分数据代表全部办理成功。

市民在未登录时尝试有效的 SSO 操作，主机会在原计划插入 `host_authentication` 登录步骤并立即展示模拟登录卡，不执行接口、不反复要求模型重排。通过页面登录后续办原目标，保留已验证的参数。模型自行提出登录时也会校验确有需要；审查器接收受信的登录状态和操作鉴权类型。此为主机控制流程，不能宣称该登录步骤由模型自主规划。

照片通过 `request_input(kind=file)` 的原生文件选择器提交，本 POC 上限为每文件 512 KiB（本地限制，并非文档条款）。选择仅保存字节，不发业务请求；`upload_selected_file` 先出上传确认，确认后由主机提供原始字节与文件名调用附件 API。字节不进入模型上下文；`execute_confirmed_submission` 复用已获授权的原始参数。上传与公共表单提交是两次独立写入，各有明确确认；返回的真实 `fileId` 才能用于表单。SourceSystem `BALADY Assistant POC` 与 Category `Initial` 为本地适配元数据，真实环境需提供方确认。

市民上传必须匹配本会话实际选过的字节，原始上传工具也不能绕过。已有事项的 SSO 文件上传仍需要可信的 NationalID、Category、CaseID，不能猜身份。仿真下载按实际返回字节提供普通下载链接；文档未明确的真实 SSO 流编码不自动猜解。

事项历史和详情只显示当前模拟身份可见的记录，事件、市政请求与咨询的详情类型不能互用。目录包含多个不同资产和分类，不能默认选第一项。当前没有地址到行政区编号/坐标的解析服务；缺少可信地理信息时说明限制，不能逼市民提供内部编号或猜测。公共投诉属于另一种诉求，必须先询问用户是否选择。仿真记录保存在当前会话，不代表跨会话政府业务台账；无法据此认定正式受理或官方 SLA。

`crm_get_closure_reasons` 必须先于同一事件和同一 `IsProcessed` 的 Madinati 处理，提交其返回的 **Name**。公共表单附件先上传，再使用返回 `fileId` 作为 `AttachmentID`。SSO 文件上传的 `LinkedRefTo` 才能作为下载 `FileKey`。完整 `pzInsKey` 保留空格、前缀及标点，URL 编码一次。

现有 `.env` 的 DeepSeek key 不覆盖、不打印。网站仍要求原有访问认证；Neon 数据库环境变量保持不变。新增真实模式配置说明见 `.env.example`，当前部署保持仿真。

旧业务 API 的 `/mock/*` 返回 410，当前 Agent 不绑定旧工具。原数据和测试源文件均保留，`datasets/registry.json` 显式标记禁用；当前测试命令只运行 CRM 测试。原 Road API 的已存草稿不能用于新的 CRM 工具。独立情绪数据保留，不把历史 mock 测试分数混入 CRM 指标。

自然业务测试的 40 个场景按 12 个开发/28 个首次保留集划分，输入、参考和仿真数据分离并固定 SHA-256。模型不见预期 API、步骤或参考答案。保留集首次运行和失败逐案保留，修复后只称回归，不能重新称盲测。评分器按实际交付给模型的事实判定；仅在未来澄清中出现的目标不能偷作当前已知事实。自动评分与独立业务语义、浏览器测试分别报告；诚实说明不支持服务或地理解析缺口不等于成功办成业务。

测试 actor 对服务选择只传递预先声明且与当前可见 ID 或标签精确一致的选项，不按参考答案、语义猜测或首项代答。没有这种明确选择时停止在待输入状态，未交付的后续脚本不能当成模型已知事实。该适配只扩展 UI 输入传输，冻结场景、参考、仿真数据和评分规则不因新控件改变。

市民缺少市政地区信息时，主机只问城市或市政地区的名称，不展示内部枚举码。`MunicipalityID` 的 17 项名称映射来自附件 3.37.8（印刷页 116 / PDF 页 117）；阿语保留来源名称，中英名称为展示翻译。混合缺项先澄清城市，保留已知草稿，后续继续必要事实。该名称表不是地址解析器：没有可信上下文提供下级行政编码时，主机拒绝要求市民填写内部 `SubMunicipalityID` / `Sub_SubMunicipalityID`；原业务仍未完成，不能猜编码、伪造坐标或替用户改成另一种业务。

位置受阻会记录为当前原请求内的主机约束和受阻步骤；审查器将其作为真实控制证据，不能当作成功回执、失败的政府调用或提交授权。最终解释由 `location_unavailable` 明确显示缺少地址到下级地区的解析能力。补充的位置资料经过参数和来源检查后，或相同操作真实成功后，才清除对应约束；不同原请求不复用。市民补问 `pzInsKey` 会使用实际本人历史生成原生选择卡，已有有效选择不会重复索取；选择“都不是”后显示未找到目标及已排除记录，不再强迫选择其中一件。

公共表单 `Description` 采用本地原话来源政策：整段来自实际用户消息，或通过 `description_source.quotes` 提供有序、不重叠的真实片段并按换行组合；大小写与空白变化允许。该控制元数据在 canonical 参数校验和实际 CRM 请求前剥离，不修改官方 OpenAPI 自由文本定义。来源缓存只支持恢复、不是提交授权。确认卡真正修改描述会记为新的用户输入；只改标题或格式不能替旧的无来源描述背书。来源检查限制自动翻译与润色，双模型审核仍检查引用的否定、主体、上下文与用户意图，避免断章取义。部分已知参数和完整提交使用相同来源检查，保留已知联系人、标题、附件而不要求重填。

已知缺少位置解析能力时，服务选择与计划会按 canonical 必需字段识别所有依赖该能力的路线，不能换一个 API 名称重复提供不可行服务。页面仅对当前请求内真实永久位置受阻隐藏重试，普通缺参、瞬态失败及执行结果未明仍保留相应恢复入口。公共计划的能力及依赖由模型生成，主机从实际能力映射中英阿三语行动标签，不展示模型自由草拟的步骤文字。集成测试受众继续测试原始规划接口，公开标签不能被算作模型叙述准确率。

图审使用两次独立的意图冲突和已知可行性审核，显式识别 `input`/`respond` 为主机控制节点，登录及每次精确写确认由主机插入；不要求图中提前包含未来事实、补问文字、回执或完整办理路径。内部目标/步骤注释仅是不可信意图参考。它硬拦已知的直接意图冲突、明显无关/多余写、不可用能力及真实约束冲突，不能证明尚未执行步骤的完整业务正确性。补问、参数、来源、本人目标及授权检查在实际步骤执行时继续硬拦。连续三次图审拒绝，或核验不可用，主机停止本轮自动处理并提供可读的重试/取消入口，避免无效循环；失败不计为业务完成。

`check_operation_readiness(operation, known_parameters)` 是本地只读控制工具，不是附件新增 API，不产生外部调用、业务回执、用户补问或提交授权。两次独立审查先确认操作与当前目标/已选路线一致、没有遗漏已知事实，再按 canonical 必需字段和配置记录当前请求的位置约束；无关探针不能给普通进度查询制造报修限制。最终指导码、来源问题、目标和约束接受两次独立关联审核，核对是否对应请求、未完成原因是否保留；不再把不可改的展示文字作为重写目标。最终审查失败有界停止，同一原请求已有的成功写入仍以主机回执摘要和编号展示，不能因此重复提交。

完整的显式草稿改动可以消除尚未展示的多余补问前置，但不能跳过真实待选控件、未完成业务步骤或其祖先；修改仍需完整参数/来源/语义审核和新的精确确认。有效原生案件选择“都不是”在纯查询计划中由主机立即结束为未找到目标/已排除可见记录，详情标为受阻且未调用；这是确定的用户选择控制，不计作模型自主完成详情或规划成功。混合其他业务任务仍继续评估其独立目标，不因未找到案件而一并取消。

结构化案件、提交或能力限制结果只显示主机事实与来源绑定的目标槽位，公众 `finish.message` 必须省略，不能用自由文字再断言字段要求、状态、文件能力或外部流程。若传入则返回明确错误让模型改用结构化字段，不静默吞掉说明。未接入业务的具体目标由 `unavailable_action_quote` 引用当前真实用户原话；其他尚未证实的问题可用 `unconfirmed_fact_quote`，需实际回执、当前原话来源检查及两次独立的事实存在/证据边界审核。它仅表示本次证据不足，不表示接口未接入、政府全系统不存在或第三方归属。目录和一般无结构化主机结果的答复仍可使用经过双审的 `message`，该路径仍有模型概率性错误。

最终两次关联审核只检查指导码、来源问题、目标和真实回执/约束是否适用于当前诉求，不要求重写不可改的主机措辞或补充自由说明。`Open` 的固定本地翻译“未结案”不意味着分派、受理或现场施工。若最终关联审核或运行失败，只保留实际操作路线发现位置不足的观察，并说明与原诉求的最终关联尚未核实，不能把已被拒绝的关联重新当作原诉求失败原因。该路线保持受阻并隐藏无效重试；同一原请求的成功写入回执仍保留。恢复会标明 `host_constraint_observation_fallback` 与错误码，不计作模型独立答复成功；正常通过关联审核才显示原报修的明确位置阻断原因。

案件审查显式接收当前请求的本人历史回执、选择状态和实际详情目标。查询回执编号是证据引用，不是已选案件编号；候选、未找到或“都不是”不构成正向关联，也不证明政府全系统不存在或第三方所有权。所有文字和目标审查连续三次拒绝后停止，避免在不可修改的回执上反复循环；已成功的本轮写入仍保留。

`action_unavailable` 还需 `unavailable_action_quote`，先由主机验证是当前原请求及其后实际用户消息的连续原话，再由两个独立会话检查请求意图和已连接能力。查询历史/进度、情绪、缺参、未知事实或暂时读取失败都不能据此变成未连接服务。该字段只用于本地控制，不进入官方 API 参数；不要求市民懂 API 或重新复述。真实引用仅证明词源，语义审查仍可能误判，不能宣称消除了模型错误。

公众工具另共享 `src/crm/public-capabilities.mjs` 中的业务效果清单：20 项工具逐一列出实际产物和是否需要受益人登录。主模型、工具说明、契约查询和所有审核场景使用同一来源。创建 CRM 请求、咨询、技术支持或公众联系记录，不等于办理其讨论的许可、缴费、退款、重开、派遣或维修；机构回调仍不向公众开放。读取状态、修改状态、字段未知、尚未执行查询是不同含义；下载已连接仍需实际文件引用和成功内容，缺少引用不能说整个下载能力未接入。公开联系表使用消费端认证，不要求受益人模拟登录。该清单是本地受众与效果边界，保留完整官方契约，不扩张 API 的业务承诺。

当主机已经显示实际回执时，禁止自由补句也覆盖重复清单及重复表格；既有表格格式检查继续保留并复用公开文字换行规范化。源绑定的问题槽位只标明具体目标或尚未证实的询问，不允许额外的无来源事实。关联审核仍要检验用户目标到指导/操作的映射，主机字段正确不等于动态计划正确。

未连接官方联系方式或办理事务目录；具体官方电话、网址和某渠道可办理特定事务的说法需有实际已验证 FAQ 来源。API 的品牌或 `sourceSystem` 示例不是办理依据。没有来源时可泛称另走独立官方渠道，不能提供凭模型记忆生成的具体指引，更不能让外部渠道追踪本地仿真编号。
