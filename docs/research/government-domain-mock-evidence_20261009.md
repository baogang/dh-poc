# 政府业务域与 POC 模拟接口的官方证据

核验日期：2026-10-09。范围仅为 BALADY、SAKANI、940、FURAS 的公开职责和术语；采用政府/平台官方网页，只读查阅，未登录账号、办理业务或提交信息。本文为 POC v0.4 提供业务语义依据，不是官方接口文档。

## 四域映射与边界

| 业务域 | 已核验的官方公开业务 | 可用于 POC 的映射（自定义模拟） | 必须保留的区别 |
| --- | --- | --- | --- |
| BALADY / بلدي | 官方市政服务目录列有建设许可；地方政府的“签发建设许可”服务链接指向 Balady。部门官网“我的请求—私人规划批准”也明确通过 Balady 提供，产品名为私人规划批准。 | 建设许可申请/状态查询；规划申请/资料查询。 | 将“土地”细化为规划或许可场景；不能据此宣称 Balady 负责全部土地所有权、住房支持或投资机会业务。[建设许可](https://hafar.momah.gov.sa/ar/node/3497)、[私人规划请求](https://momah.gov.sa/ar/e-services/tlbaty-atmad-almkhttat-alkhast) |
| SAKANI / سكني | 官方资格核验服务基于批准条件判断住房支持资格；可在未符合资格时重新申请或提出异议。相关产品包括住宅单位、住宅用地支持和自建住房方案。 | 查询预置的 mock 住房支持资格及申请状态；解释 mock 缺失资料或异议流程。 | “补贴”应限定为住房支持；预置资格、金额、材料和拒绝原因不代表真实政策或审批结果。[住房支持资格核验](https://sakani.sa/services/check-eligibility) |
| 940 | 官方地方政府服务页定义为：用户按分类登记市政报告，由市政领域主管单位处理；服务链接指向 Balady。部门官网同时说明 Balady App 可提交并跟踪报告。 | 报事/投诉草稿、位置与分类补充、mock 工单查询；在测试中区分抱怨情绪和明确报事意图。 | 940 是业务渠道/服务名称；以独立 adapter 模拟，不证明真实后端与 Balady 分离，也不证明存在公开 940 API。[940 服务](https://hafar.momah.gov.sa/ar/node/3513)、[Balady App](https://momah.gov.sa/ar/node/3453) |
| FURAS / فُرص | 官方介绍定位为管理和发布政府房地产及市政投资机会的门户；公开旅程包括浏览机会、购买招标文件、提交报价和签署合同，机会分布于不同地区及行业。 | 以一个 mock 业务 Agent 接口承接城市/行业筛选、机会详情和投标材料解释；与另外三个 tool/skill adapter 对比。 | “通过 Agent 接入”是用户指定的 POC 技术假设，未核验为官方 Agent endpoint；不能推断收益、资格、获标概率或合同条款。[官方门户介绍](https://furas.momah.gov.sa/ar/about) |

以上信息支持业务命名和模拟对话，不支持声称发现可直接调用的官方 API。三个 API adapter 与一个业务 Agent adapter 的划分属于 POC 架构选择，真实系统数量、身份系统和集成边界仍待接口方确认。

| 域 | 已在所引官方网页出现的术语 | 对应中文 |
| --- | --- | --- |
| BALADY | إصدار رخصة بناء；اعتماد المخططات الخاصة；طلباتي；الرخص الإنشائية | 签发建设许可；私人规划批准；我的请求；建设许可类服务 |
| SAKANI | التحقق من استحقاق الدعم السكني；أهلية；رفع طلب اعتراض；أرضك دعمك；حلول البناء الذاتي | 住房支持资格核验；资格；提出异议；住宅用地支持产品名；自建住房方案 |
| 940 | البلاغات والشكاوي；بلاغ；جهة الاختصاص؛تصنيفات；تقديم البلاغات ومتابعتها | 报事与投诉；报告/报事；主管单位；分类；提交并跟踪报告 |
| FURAS | الفرص الاستثمارية؛شراء الكراسات；تقديم العروض；توقيع العقود；القطاعات الاستثمارية | 投资机会；购买招标文件；提交报价/投标；签署合同；投资行业 |

术语来自上表链接。“بلاغ”不能在所有语境中一律译为投诉；对话标签可分别记录 `municipal_report` 与 `complaint_about_service`，后两者为 POC 自定义语义标签。

## 模拟数据与回归的具体约束

- 使用 `mock_balady.*`、`mock_sakani.*`、`mock_940.*`、`mock_furas_agent.*` 等明确命名；接口路径、schema、枚举、响应时限、工单状态、审批原因、资格和金额均须注明“POC 自定义”。这些名称是建议，不是官方接口。
- “我要一块地”应加入歧义场景：住宅用地支持、规划/建设许可、投资机会可能指向不同域；信息不足时预期补问用途，而不是仅凭关键词路由。
- “我很生气”单独作为情感信号；只有报事内容或明确诉求才决定 940 路由。建设许可逾期的抱怨也可能仍属于 BALADY 状态查询，需要标注用户当前意图。
- 多域场景可以模拟“先了解住房支持，再了解自建许可”或“查询投资机会，随后询问建设许可”；这些是测试编排，未由公开网页证实为真实系统自动串联流程。
- 投标、投诉提交、许可申请等 mock 写操作应有明确草稿与确认状态；结果只可陈述模拟系统返回的事实，不能产生真实办理成功的表述。

## 未核验与不应推断的内容

1. 本次未取得四域正式 API/OpenAPI、Agent 协议、鉴权方式、字段和错误码；网页上的“开始服务/服务链接”不等于接口授权。
2. 940 的地方政府页面说明分类和主管单位处理，但不完整定义全国分类、升级/重开机制或统一状态机；不能将所设计的状态写成官方状态。
3. SAKANI 的通用资格说明不够用于实现真实政策引擎；本次不推断年龄、收入、家庭、补贴金额、材料或审核门槛。不同住房产品的规则仍应查各产品当前规则。
4. FURAS 的门户职责不代表每个机会的条件一致，也不保证收益或获标；投标条件应以真实机会文件为准。POC 可以用虚构机会和虚构条款，只需明确标注。
5. BALADY 的“我的请求”页面属于特定服务视图；其展示的免费/即时/无需材料不能泛化为所有规划审批或建设许可。
