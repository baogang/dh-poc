01

先判断能否直接回答，再规划业务

FAQ 只返回现有知识库内容；创建、查询、关闭、投诉、转人工等办理请求会进入业务 Agent。一般问候或能力范围外的问题可以直接结束。

两种确认，作用不同。审阅计划只批准处理步骤；创建、关闭、投诉和转人工仍需单独核对具体提交内容。查询无需提交确认，但同样需要计划批准与登录身份。

FAQ 插问保留待办。业务意图发生变化时，旧授权会失效，Agent 重新规划；运行中的任务需要先停止，才能发送另一条消息。

02

每次调用都经过约束，结果再反馈给 Agent

“计划→工具→观察→下一步”可以连续执行；缺少信息或未获授权时，本轮结束并等待。用户操作后，服务端把已有事实、计划和回执注入新的 PI 会话继续处理。

Harness 负责校验。工具必须对应获批步骤，依赖先完成，已知参数保持一致；User ID 由后端注入。关闭、投诉、转人工前要查本人历史；转人工还校验工单匹配、仍未解决及非终态。

校验失败或 API 失败会作为错误观察返回，Agent 可修正调用、重新规划或说明受阻；不会凭空生成成功回执。

确认后也要重新选用工具。授权绑定具体计划、步骤、操作、参数与当前执行轮次；确认后恢复 PI，再校验并调用相同操作。文字“同意”不等于后端授权。

HTTP 遇 503 仅用同一幂等键重试一次；已完成步骤复用已有回执，避免重复提交。

03

工具边界与代码落点

8 个自定义 Tools，6 个 MOCK API

业务工具 5 个：查询、创建、关闭、投诉、转人工。控制工具 3 个：发布计划、请求输入、结束。登录是第 6 个 API，由表单和服务端调用，密码不进入模型；当前没有加载 SKILL 或扩展插件。

类别已注册能力
业务query_tickets · create_ticket · close_ticket
complain_ticket · handoff_to_human
控制propose_plan · request_input · finish
知识库门控select_faq 属于独立 FAQ 会话，不计入业务 Agent 的 8 个工具。

状态让循环可以暂停和恢复

RoadStore 保存对话、计划版本、已知事实、待输入、待确认、授权、回执和事件。前端通过 SSE 获取更新，3 秒轮询作恢复补充；聊天内任务完成后划线。

单轮业务执行上限：12 次模型请求、24 次工具尝试、180 秒。停止会终止当前执行并撤销未使用的授权；finish(completed) 依据真实回执展示业务结果。

当前 MOCK 与应用位于同一服务，通过私有 HTTP 适配器调用；图中的 API 不是已对接的真实外部工单系统。
